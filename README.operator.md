# F1 한국어 캘린더 운영자 안내

[사용자용 안내와 캘린더 구독으로 돌아가기](README.md)

공식 F1 원본을 읽어 한국어 캘린더를 운영하는 사람을 위한 설치·유지보수·개발 문서입니다. Google Apps Script의 시간 트리거로 실행하며 별도 서버나 켜 둔 PC가 필요 없습니다.

## 운영 상태

**2026년 9월 25일 설치 확인 기준**입니다. 일정 수는 이후 원본 갱신에 따라 달라집니다.

| 항목 | 확인 결과 |
| --- | --- |
| 일정 등록 | 2026년 50개 + 2027년 110개 = 160개 세션 |
| 재실행 검증 | 변경 없음 160개, 생성·수정·삭제·남은 작업·경고 모두 0 |
| 마지막 수동 동기화 성공 | 2026-09-25 16:04:55 KST |
| 자동 실행 | `syncNow` 매시간 트리거 설치 완료 |
| 공개 구독 | 로그인 없는 공개 ICS 조회 성공, 일정 160개·서로 다른 UID 160개 확인 |

시간 기반 트리거의 실제 예약 실행과 휴대폰 알림 수신은 아직 별도로 확인하지 않았습니다. 원본의 2027년 일정에는 시간 미정 항목이 포함되어 있으며, 수신 사실이 날짜·시간의 최종 확정을 뜻하지는 않습니다.

```text
F1 공식 구독 → 내 구글의 원본 캘린더 → Apps Script → F1 한국어 → 다른 사람의 구독
```

| 세션 | P1 · P2 · P3 · Q · SQ · S · G |

| 설명 | F1 경기 페이지 링크 하나. 없으면 해당 시즌의 공식 일정 링크 |

| 시간 미정 | 날짜가 있으면 종일 일정, 알림 없음. 시간이 나오면 같은 일정을 갱신 |

| 새 대회·서킷 | 번역이 없으면 임시 영문명과 누락 기록 |
| 갱신 | 매시간 및 수동 실행. 공식→구글 반영 지연은 별도 |
| 취소·제거 | 해당 관리 일정 삭제. 조회 실패 시 삭제하지 않음 |
| 다음 시즌 | 2026년 이후의 원본을 연도 상한 없이 처리 |
| 공유 | 검증 후 읽기 전용 공개, 구독 링크 생성 |

## 직접 운영하기: 설치

[공개 캘린더](README.md) 대신 본인 계정에서 별도의 한국어 캘린더를 운영하려는 경우에 진행합니다. 새로 생성한 캘린더의 구독 주소는 마지막 단계의 실행 로그에서 확인할 수 있습니다.

### 1. 공식 캘린더 구독

[F1 공식 구독 페이지](https://calendar.formula1.com/)에서 Google Calendar로 구독합니다. 파일 한 번 가져오기 대신 갱신되는 구독을 사용하세요.

구글 캘린더에 별도 F1 원본이 생기고 실제 일정이 보이는지 확인합니다. 구독 과정에서 기본 캘린더로 개별 일정을 복사하는 방식만 제공된다면 이 구현의 원본으로 사용하지 말고, 별도 구독 캘린더가 만들어지는 경로부터 확인해야 합니다. 기본 캘린더는 원본·대상 모두에서 거부합니다.

### 2. 붙여 넣을 파일 만들기

Node.js 18 이상에서 실행합니다. 외부 npm 패키지는 필요 없습니다.

```sh
npm run check
```

`dist/Code.gs`와 `dist/appsscript.json`이 생성됩니다. 원본 코드는 `src/`에 있고 `dist/`는 재생성 가능한 배포용 파일입니다.

### 3. Apps Script 프로젝트 설정

1. [Google Apps Script](https://script.google.com/)에서 **공식 캘린더를 구독한 본인 계정**으로 새 프로젝트를 만듭니다.
2. 기본 `Code.gs` 내용을 `dist/Code.gs` 전체 내용으로 교체합니다.
3. 프로젝트 설정에서 **편집기에 appsscript.json 매니페스트 파일 표시**를 켭니다.
4. `appsscript.json`을 `dist/appsscript.json` 내용으로 교체하고 저장합니다. 시간대는 `Asia/Seoul`입니다.
5. 서비스에 **Google Calendar API v3**, 식별자 **Calendar**가 표시되는지 확인합니다. 없으면 서비스의 `+`로 추가합니다. 표준 Cloud 프로젝트를 직접 연결했다면 해당 프로젝트에서도 Calendar API를 활성화해야 합니다.
6. 함수 목록에서 `listCalendars`를 실행하고 본인 계정의 캘린더 및 트리거 관리 권한을 승인합니다.
7. 실행 로그에서 공식 F1 캘린더의 `id`를 찾아 코드 맨 위 `F1_CONFIG.sourceCalendarId`에 넣습니다.

```js
sourceCalendarId: '여기에 Google 캘린더 ID',
```

구글 캘린더 설정 → 원본 F1 캘린더 → 캘린더 통합에서도 ID를 확인할 수 있습니다. **ECAL의 `KR-F1`이나 `63ed...` 일정 ID와는 다릅니다.** 비밀 iCal 주소나 비밀번호는 필요 없습니다. 캘린더 ID·계정별 상태는 공개 저장소에 올리지 않아도 됩니다.

웹앱으로 배포할 필요는 없습니다. 스크립트 편집기에 저장한 코드와 설치형 시간 트리거로 실행됩니다.

### 4. 실제 원본 확인 후 비공개 동기화

아래 함수를 순서대로 실행합니다.

| 순서 | 함수 | 확인할 결과 |
| --- | --- | --- |
| 1 | `previewSync` | 읽기 전용 미리보기. 제목, 시간, 장소, 제외 항목, 경고 확인 |
| 2 | `setupCalendar` | 본인 소유의 **비공개** `F1 한국어` 생성. 재실행해도 중복 생성 없음 |
| 3 | `syncNow` | 최초 일정 반영. `remaining`이 0이 될 때까지 반복 |
| 4 | `syncNow` | 다시 실행해 불필요한 생성·수정·삭제가 없는지 확인 |
| 5 | `previewSync` | `changes`가 빈 배열인지 확인 |

일반 경기 주말의 P1/P2/P3/Q/G, 스프린트 주말의 P1/SQ/S/Q/G가 정확한지 실제 구글 캘린더와 공식 경기 페이지를 비교합니다. 스프린트가 없는 주말에 S/SQ를 임의로 만들지 않습니다.

소유자의 구글 캘린더 **설정 → 시간대**를 한국으로 맞추고, 휴대폰과 구글 캘린더 앱 알림도 허용하세요. 캘린더 시간대를 설정하는 것만으로 다른 사람의 화면 시간대까지 강제하지는 않습니다.

경고 `UNCLASSIFIED`가 있으면 원본의 세션 제목을 식별하지 못한 상태입니다. 이 경우 누락 추정 삭제와 공개를 보류합니다. 번역 누락만 있는 경우에는 영문 임시 일정으로 정상 운영할 수 있습니다.

실제 원본에서 확인한 `Formula 1 in your calendar!`는 ECAL 구독 안내이므로 제외합니다. 이 제목은 전체 일치로만 제외하며, 다른 미분류 제목은 계속 경고로 남깁니다.

미리보기 로그에는 변경 수, `seasons`의 시즌별 개수, `warningCounts`의 경고별 개수, 제한된 경고 예시를 출력합니다. 미분류·날짜 누락 항목은 각각 **확인 필요** 줄에 따로 출력하며, **변환 예시**에는 한국 시간으로 표시합니다. 전체 변경 목록을 한 로그에 출력하지 않아 대량 일정에서도 로그가 잘리지 않습니다.

공식 원본의 장소가 국가명뿐이면 대회명과 국가를 함께 확인해 `국가 · 서킷명`을 표시합니다. 예를 들어 같은 `United States`라도 미국·마이애미·라스베이거스 GP의 서킷을 구분합니다. 확인된 시즌별 개최지 변경은 `F1_VENUE_OVERRIDES`에서 처리하고, 새로운 개최지로 추정되는 경우에는 한국어 국가명을 유지하며 `VENUE_UNCONFIRMED`를 기록합니다. 실제 서킷명이 제공되면 `F1_VENUES`에 기록한 해당 서킷의 국가를 사용합니다.

### 5. 자동 실행과 공개 구독

1. `installHourlyTrigger`를 실행합니다. 재실행하면 기존 동일 함수 트리거를 교체해 하나만 유지합니다.
2. 정상 동기화를 두 번 완료하고 변경 없음 상태에서 `publishCalendar`를 실행합니다.
3. 실행 로그의 `google` 링크를 구독자에게 전달합니다. `web`은 보기 전용 웹 캘린더, `ics`는 다른 앱용 공개 구독 주소입니다.
4. 다른 계정이나 로그아웃 상태에서 일정이 보이고 편집할 수 없는지 확인합니다.
5. 원본 F1 캘린더는 구글 화면에서 체크를 해제해 숨깁니다. **구독을 해제하거나 원본 일정을 삭제하지 마세요.**

`publishCalendar`는 스크립트가 생성한 대상만 공개하며, 대상에 수동으로 만든 일정이 있으면 공개를 중단합니다. 공개한 뒤에도 이 캘린더에는 개인 일정을 넣지 마세요. Workspace 조직 정책이 공개를 막으면 계정 관리자 설정에 따라 공개할 수 없습니다.

**구독자의 알림은 별도입니다.** 각 구독자는 구글 캘린더의 해당 캘린더 설정에서 기본 이벤트 알림을 1시간 전으로 설정하고 앱 알림을 허용합니다. 소유자의 알림은 모든 구독자에게 강제로 적용되지 않습니다. 시간 미정 종일 일정에는 구독자도 종일 일정 알림을 별도로 켜지 않는 것을 권장합니다.

## 삭제와 장애 처리

- 공식 제목에 `CALLED OFF`, `CANCELLED`, `CANCELED`, `ABANDONED` 또는 `취소`가 있으면 해당 세션을 삭제합니다. 대회 전체 취소 공지이면 그 시즌의 대회 세션들을 삭제합니다.
- 원본의 모든 페이지를 정상 조회한 뒤, 사라진 미래 일정은 삭제합니다. 진행 중이거나 끝난 일정은 단순 누락만으로 삭제하지 않습니다.
- 원본이 통째로 비거나 삭제 흔적만 남으면 두 번 연속 정상 동기화로 확인합니다. 미리보기는 확인 횟수에 포함되지 않으며 조회 실패는 횟수를 초기화합니다.
- 과거 원본이 정리되며 사라진 일정은 보존합니다. Google의 삭제 흔적만으로는 경기 취소와 원본 보관 기간 만료를 구분할 수 없으므로, 과거 일정은 명시적 취소 문구가 확인될 때만 삭제합니다.
- 날짜·시간이 미확정이거나 제공 형식을 분류하지 못하면 기존 일정을 삭제하지 않습니다. 다음 조회에서 다시 확인합니다.
- 읽기 권한 상실, 페이지 오류, 잘못된 응답, 중복 세션이면 쓰기 전에 중단합니다. 실제 API 쓰기가 중간에 실패하면 앞서 반영된 일정은 남고, 다음 실행이 전체 대조하여 이어갑니다.
- 대상 일정에 저장한 비공개 관리 태그로 소유권과 원본 연결을 추적합니다. 수동으로 만든 일정은 동기화가 수정·삭제하지 않습니다.
- 한 번에 최대 80개 변경, 실행 시작부터 4분을 기준으로 다음 실행에 작업을 넘깁니다. 대량 최초 등록은 `syncNow`를 반복 실행할 수 있습니다.
- 취소됐다 다시 생긴 경기와, 네트워크 오류 직전에 이미 등록된 경기도 중복 없이 복원·재확인하도록 ID를 관리합니다.

## 운영과 다음 시즌

### Apps Script를 배포해야 하나요?

**별도 배포 없이 그대로 두면 됩니다.** `installHourlyTrigger`를 실행하면 저장된 프로젝트의 `syncNow`가 Google 서버에서 매시간 실행됩니다. 편집기와 브라우저를 닫거나 PC를 꺼도 동작하며, 매번 실행 버튼을 누를 필요가 없습니다. 이 프로젝트는 설치형 시간 트리거를 사용하므로 **배포 → 새 배포** 절차가 필요하지 않습니다. [Google의 설치형 트리거 안내](https://developers.google.com/apps-script/guides/triggers/installable)를 참고하세요.

`publishCalendar`는 Google Calendar의 읽기 전용 공개 설정을 적용하는 함수입니다. 구독자는 공개 캘린더를 추가하며 Apps Script 프로젝트에 접근하지 않습니다.

운영 중에는 다음 설정을 유지합니다.

- Apps Script 프로젝트, 설치한 시간 트리거, 실행 계정의 캘린더 접근 권한을 유지합니다.
- 원본 `Formula 1` 캘린더는 표시 체크만 해제해 숨길 수 있습니다. 원본 구독은 유지합니다.
- 프로젝트 설정의 스크립트 속성에 저장된 `F1_TARGET_CALENDAR_ID`와 `F1_SYNC_STATE`를 유지합니다. 대상 캘린더와 동기화 기록을 이어 사용하는 데 필요합니다.

매시간 실행은 정확히 매시 정각 실행을 뜻하지 않습니다. 공식 공급자가 원본 Google 캘린더를 갱신하는 시간, 이 스크립트가 조회하는 시간, 구독자 앱이 갱신하는 시간이 더해질 수 있습니다.

### 자동 실행 확인과 코드 갱신

설치 후 다음 예약 실행을 확인하려면 Apps Script 왼쪽 **실행**에서 시간 기반 트리거로 실행된 `syncNow`의 완료 여부를 봅니다. `showStatus`에서는 `triggers: 1`, `state.lastSuccessAt`, `state.remaining`을 확인할 수 있습니다. 수동 실행도 성공 시각을 갱신하므로 자동 실행 여부는 실행 기록에서 구분합니다. 로그의 `Z`로 끝나는 시각은 UTC이며, 한국 시간은 9시간을 더합니다.

코드를 바꿀 때는 로컬에서 `npm run check`를 실행한 뒤 같은 Apps Script 프로젝트의 `Code.gs`를 새 `dist/Code.gs` 전체 내용으로 교체하고 저장합니다. 매니페스트도 바뀌었다면 `appsscript.json`을 함께 교체합니다. `sourceCalendarId`와 기존 스크립트 속성을 유지하고 `previewSync` → `syncNow`로 확인하세요. 같은 `syncNow`를 계속 사용하면 기존 트리거와 구독 링크를 유지하며 별도 재배포도 필요 없습니다. 새 권한이 추가된 변경은 직접 실행해 권한 승인을 완료합니다.

### 관리 함수

| 함수 | 용도 |
| --- | --- |
| `showStatus` | 최근 실행·성공 시각, 변경 수, 오류·경고, 남은 작업, 트리거 수 |
| `previewSync` | 쓰기·상태 변경 없이 변경 예정 내용 확인 |
| `syncNow` | 지금 동기화 |
| `getSubscriptionLinks` | 기존 대상의 공유 주소 확인 |
| `uninstallHourlyTrigger` | 자동 실행만 해제. 캘린더와 기록은 유지 |

Apps Script의 **실행** 화면에서 실패 기록을 확인할 수 있습니다. 설치형 트리거 실패 알림은 Google의 기본 알림 기능을 사용하며 별도 메일 발송 코드는 없습니다. 번역 누락처럼 실행 자체가 성공한 경고는 `showStatus`와 실행 로그에서 확인합니다.

연도 상한을 두지 않고 원본이 제공하는 2026년 이후 일정을 조회합니다. 2027년, 2028년 일정이 같은 구독에 들어오면 자동 반영합니다. 아직 공개되지 않은 경기나 시간을 추정해서 생성하지 않습니다.

공식 연결이 바뀌면 `uninstallHourlyTrigger` → 새 공식 구독 추가 → `sourceCalendarId` 변경 → `previewSync` → `syncNow` → `installHourlyTrigger` 순으로 교체합니다. 기존 대상 캘린더 ID는 그대로 둡니다. 대회·시즌·세션이 유일하게 대응하면 기존 대상 일정을 이어 사용합니다. 새 원본으로 대응되지 않는 이전 원본의 일정은 자동 삭제하지 않으므로 미리보기의 `preserved`와 실제 캘린더를 확인하세요. 매칭이 불명확한 일정은 임의로 합치지 않습니다.

새 번역은 `src/Config.js`의 `F1_RACES`, `F1_VENUES`, `F1_COUNTRIES`에 추가하고 시즌별 개최지 변경은 `F1_VENUE_OVERRIDES`에 반영합니다. 소스에서 수정했다면 위 코드 갱신 절차대로 Apps Script에 반영하세요. Apps Script 편집기만 수정했다면 나중에 로컬 빌드 파일로 덮어쓸 때 설정을 다시 넣어 주세요.

## 개발과 검증

```sh
npm test       # Node 내장 테스트 러너, 외부 의존성 없음
npm run build  # 하나의 Code.gs와 매니페스트 생성, 구문 검사
```

`src/Core.js`는 구글 API에 의존하지 않는 분류·변환·대조 로직입니다. `src/Main.js`는 Apps Script API, 페이지 조회, 잠금, 상태 저장, 공개 설정을 담당합니다. 테스트는 시간대·시즌 전환·삭제뿐 아니라 API 모의 객체로 페이지 조회 실패, 부분 실행, 재시도, 공개·트리거 중복 방지까지 확인합니다. 실제 Google API 실행이나 F1 공급 형식 검증을 대신하지는 않습니다.

테스트에는 사용자가 제공한 실제 제목·장소와 합성한 날짜·시간을 사용하며, 전체 원본을 캡처한 데이터는 아닙니다. 실제 계정에서 확인한 등록·재실행·공개 조회 결과는 위 운영 상태에 별도로 기록합니다.

현재는 공식 구독이 제공하는 개별 세션을 대상으로 합니다. 반복 일정 형식으로 제공 방식이 바뀌면 잘못 확장하지 않고 점검을 위해 중단합니다.
